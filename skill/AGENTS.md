## 2. 两个"不要再踩"的大坑（本工程最大的时间黑洞）

### 坑 1：卡在逻辑分析仪打不开时，**不要去修 Windows 驱动**

症状：`fx2lafw: Failed to open potential device with VID:PID 1d50:608c: LIBUSB_ERROR_NOT_SUPPORTED`，
但 `sigrok-cli --scan` **能列出设备**（连序列号都读得到）。PnP 显示 `Status=OK`、
驱动 `WinUSB`、设备接口 GUID 已注册 —— 一切正常。

**真相**：sigrok 的 Windows 构建（含最新 nightly）都静态链接同一个 **2016 年的
`libusb 1.0.20.11003-rc3`**，它内部的 API 类型派发在某些 Windows 状态下必然失败。
`libusb_open()` **不做任何 USB 通信**，纯按注册表元数据派发 ⇒ **与接线/供电/固件/驱动无关**。
重装驱动、删驱动包、重启、换 USB 口**全部无效**（实测过）。

**正解**：**绕开它。** 用官方新版 libusb 自己抓 → 见 `tools/fx2cap.cjs`（已实现并跑通）。

### 坑 2：fx2lafw **没有 STOP 命令**，抓取前必须 USB 复位

协议里只有 `GET_FW_VERSION / START / GET_REVID`，**没有 STOP**。主机一旦停读，
FX2 的 FIFO 填满就**卡死**，表现为"**只发一包然后全是 timeout**"。
被强杀进程中断的采集尤其会留下这个状态。

**正解**：`fx2cap.cjs` 每次抓取前自动 `libusb_reset_device`（可用 `--no-reset` 跳过）。
另外：**直接 kill 抓取进程会丢掉全部数据**（采样缓冲只在结束时写盘）——
需要开放式长时间抓取时用 `--stopfile <path>`。

> 其他高频坑（共地、1 采样宽毛刺骗过解码器、STM32 BRR 公式、115200 在 250 kHz 下解不出等）
> 见 `LESSONS.md`。

## 3. 协议速查（完整版见 `PROTOCOL.md`）

**物理层**：UART **9600 8N1**，空闲高。三根信号：
`D0`=主机→探头、`D2`=探头→主机、`D4`=静态控制线（**可悬空**，与复位/清零无关）。

**主机命令（都带 CRC-16/MODBUS 小端）**

```
轮询（每 500 ms）  AB 20 60 00 14 00 89 07
清零               AB 21 20 00 02 00 01 00 3D 8A
```

**探头回帧（28 字节定长）**

| 偏移 | 类型 | 含义 | 单位 |
|---|---|---|---|
| 0–5 | — | 帧头 `AB 20 60 00 14 00` | — |
| 6–9 | float LE | 实时辐照度 | **µW/cm²**（表显 mW/cm² = ÷1000） |
| 10–13 | float LE | 累积能量 | **µJ/cm²** |
| 14–15 | uint16 LE | 距上次清零的时间 | **×0.1 s**（每帧 +5） |
| 16–17 | 2B | 恒 0（含义未定，已排除单位/量程） | — |
| 18–21 | float LE | **最小值 `P_MIN`** | µW/cm² |
| 22–25 | float LE | 平均辐照度 `P_AVG` | µW/cm² |
| 26–27 | uint16 LE | **CRC-16/MODBUS**(over 0–25) | — |

**关键性质**
- **帧内数值永远是 µW/cm² / µJ/cm²，不随表上的单位档变化**（已用 mW/cm² 档实测对照）。
- **最大值 `P_MAX` 不在帧里** ⇒ 表（和你自己）从实时流自行统计。
- **探头只在被轮询时回帧**（halt 主机后 D0/D2 双双静默）。
- 表**进入测量模式时会自动发一次清零** ⇒ 表上"距上次清零的时间"从那一刻起算。
- 表的设置（单位/能量显示/标准/自动关机）**不进帧**；开机时它会下发 9 条配置命令给探头，
  但**自制主机一条都不用发**（已验证）。

## 4. 怎么跑（三条命令）

```powershell
# 1) 抓取（自动 USB 复位；--stopfile 支持任意时长开放式抓取）
node tools\fx2cap.cjs --rate 250000 --ms 20000 --out captures\now.bin

# 2) 解码 + 切帧 + 逐字节变化 + 浮点字段扫描
node tools\uv-analyze.cjs captures\now.bin 250000 2 9600

# 3) 反推/验证校验和（穷举 65536 个 CRC-16 多项式）
node tools\checksum-hunt.cjs captures\now.bin 250000 2 9600
```

**采样率选择**：≥ 波特率 × 10。9600 baud 用 100–250 kHz 足够；
**115200 在 250 kHz 下只有 2.2 采样/位，解不出来**（改波特率或提高采样率）。
高采样率（≥8 MHz）本工具的单传输同步读法撑不住，需要多路并发传输才能改。

**依赖**：Node.js（自带）+ `tools/lib/libusb-1.0.dll`（官方 1.0.27，已随包）
+ `koffi`（FFI，脚本会自动在 `tools\node_modules`、DSH profile、全局里找）。

## 5. 硬件接线（自制主机读探头）

| 主机 | 接到探头的 |
|---|---|
| **USART TX**（本项目用 F103 PA9） | **主机→探头**那根线（原 LA 的 D0） |
| **USART RX**（PA10） | **探头→主机**那根线（原 LA 的 D2） |
| GND | GND（**必须共地**） |
| 5V | 5V |
| — | 第 3 根信号（原 D4）**悬空即可** |

⚠️ **原装表必须拔掉**，否则它的 TX 会和你的 TX 抢同一条线。
⚠️ **逻辑分析仪的 GND 必须接**，否则 8 个通道全部悬空读高、什么都看不到（真实踩过）。

固件参考实现：`firmware/f103_probe/main.c`（轮询 + CRC 校验 + 四字段解析 + 调试输出，
已验证 21/21 帧零错误）。另有 `firmware/f103_rgb/main.c`（同款 F103 当可控 RGB 光源，
用于做频谱响应与标定实验，含"单次脉冲"和"循环"两种模式）。

## 6. 已知未定项

- **偏移 16–17 恒 0**：含义未定。已排除"单位/量程"（切单位后不变）。不影响任何功能。
- **`AB 70 80` 命令载荷的第 9–11 字节会变**（两次开机差约 2 倍），疑似**量程/增益**。
  ⇒ **自制主机只发轮询时，探头量程停在默认档**；若把表的设置改得很偏，读数可能与表显不一致。
  **建议保持表的设置在默认档**（本项目所有逐位吻合的对照都在默认档下取得）。
